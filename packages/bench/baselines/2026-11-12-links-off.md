## Eval: hook-shaped queries (15 rows)

`pnpm eval --demo --hook` (lexical) and `--demo --hook --dense` (`fast`, no reranker: decision
3's path), links off.

| Path             | single-fact r@10 (4) | multi-hop r@10 (6) | chit-chat abstain FP (5) |
| ---------------- | -------------------- | ------------------ | ------------------------ |
| lexical          | 1.000                | 0.000              | 0.800                    |
| fast (`--dense`) | 0.750                | 0.000              | 0.800                    |

Four of the five chit-chat prompts ("thanks, that works", "lgtm, push it", ...) return at least
one memory on both paths. Links that fire on those results would add more off-topic memories to a
hook's injection, so the hook bar should watch this column as well as multi-hop recall.

Warm-up before measuring: 500 recalls at 100k (4,278 accesses recorded), 200 at 1M (1,621).
Both use the binary vector index (auto past 100,000 vectors).

**Machine load.** These runs shared a 10-core machine with several other agents' builds and
tests; the load average was between 800 and 1,000 for most of the runs, so a recall
spent most of its time waiting for a core (the 100k run's `full` path came out faster than its
`lexical` path, which only scheduling explains). Read the absolute numbers as a record that the
suite runs end to end, not as Oort's latency. The bar compares links off and links on in the same
session on the same machine; re-run both on a quiet machine before judging it.
